01 - What It Solves

Turning model capability into an operational policy analysis interface

The project translates a technical simulation workflow into an interface that supports scenario design, repeatable runs, and results communication for carbon-emission policy analysis.

01

Scenario Configuration

Configure analysis years, market assumptions, technology parameters, production constraints, and policy input files through a structured web interface.

02

Reproducible Execution

Each scenario is designed to run as an isolated job with its own request record, status file, log, and output directory.

03

Results Delivery

Summary indicators, time-series data, logs, and raw output files are organized for review, comparison, and downstream analysis.

02 - Collaboration Value

Built for policy evaluation, corporate planning, and data-driven research

The project is positioned as a bridge between regulatory policy analysis and industry decision support. It can support collaborative studies with automakers, automotive data providers, research institutes, and policy teams.

Automakers

Scenario planning for compliance and technology pathways

  • Evaluate carbon-policy pressure under alternative regulatory assumptions.
  • Compare fleet electrification, cost, and sales-share pathways.
  • Prepare internal policy response and product strategy analysis.
Data and Analytics Institutions

Model-ready data workflows for vehicle-market research

  • Connect market, fleet, price, technology, and policy datasets.
  • Turn data assets into repeatable policy-simulation scenarios.
  • Generate structured outputs for dashboards, reports, and studies.
Research and Policy Teams

Transparent assumptions and reproducible simulation outputs

  • Track assumptions, input files, logs, and output packages by run.
  • Compare baseline, strict, and customized policy cases.
  • Support academic papers, policy briefs, and stakeholder workshops.

03 - Model Scope

Scenario coverage across policy, market, technology, and compliance dimensions

The model workflow is designed around structured vehicle, market, technology-cost, policy-standard, credit, and energy input tables. This makes it suitable for scenario comparison rather than one-off static reporting.

Policy

Regulatory pathways

Carbon standards, credit parameters, new-energy vehicle requirements, upstream methods, utility factors, and required sales-share assumptions.

Market

Fleet and sales dynamics

Vehicle classes, body styles, manufacturer portfolios, sales-share behavior, price response, annual travel, and fleet turnover inputs.

Technology

Powertrain and cost pathways

ICE, BEV, and PHEV cost curves, battery demand, mass scaling, glider cost, production constraints, fuel prices, and electricity-price inputs.

Outputs

Decision-ready results

Sales, market shares, certification emissions, target comparison, battery demand, vehicle cost, credit settlement, logs, and downloadable output packages.

04 - Workflow

A complete path from policy assumptions to simulation outputs

The workflow separates user interaction from model execution. This keeps the research model traceable while creating a practical path toward shared server deployment.

Input

Define Policy Scenarios

Select baseline inputs or upload CSV files, then set policy, market, and technology assumptions.

Run

Launch Model Runs

Create a run directory, persist request parameters, and execute the simulation through a controlled runner.

Parse

Extract Summary Metrics

Parse summary outputs into key metrics, trend series, and a navigable file index.

Deliver

Deliver Results

Review run status, logs, charts, and downloadable output files from the browser.

06 - Deployment

Designed for local research use and future server access

The public project page can be hosted on GitHub Pages. The full simulation workflow requires a Python backend and can later be deployed on a controlled cloud server for authenticated access.

Local Research Mode

Run the application on a workstation and access the browser interface at `127.0.0.1:8765`.

Team Network Mode

Host the service on a shared workstation and allow collaborators on the same network to access it.

Cloud Server Mode

Deploy the application behind authentication, reverse proxy, job control, and persistent result storage.

# local preview
python web_app.py

# browser
http://127.0.0.1:8765

# server / LAN
$env:APP_WEB_HOST="0.0.0.0"
$env:APP_WEB_PORT="8765"
python web_app.py

08 - Data and Traceability

Structured inputs and run records support review and collaboration

The workflow records input metadata, file versions, checksums, request parameters, run status, logs, summary outputs, and detailed output packages. This is useful for validating assumptions and comparing policy cases across teams.

Input registry

Policy, market, technology, vehicle, energy, and cost inputs are organized as versioned tabular files with metadata and checksums.

Run traceability

Each scenario can preserve request parameters, status records, logs, summary files, and output folders for later audit.

Comparative analysis

Baseline, strict, and customized policy cases can be compared through consistent indicators and downloadable result packages.
